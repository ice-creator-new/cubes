# 功能细节

这是 README 原来「已实现」一节的全部条目，按主题分组，条目本身没有改写。逐项的接口、字段和取值以代码为准。

## 项目形态

Python/FastAPI 后端，配两个客户端：原生 SwiftUI iOS 应用，以及仿 Grok 界面的 Web 客户端（同一套代码用 Electron 打包成桌面应用）。用户只和一位主管对话；主管按目标自己创建成员、建群、分派任务并汇总。没有预设角色，也没有本地假回复。

## 历史数据

旧圆桌会话会在首次启动新后端时迁成只读群组：话题、发言顺序、作者名和角色快照都保留，旧角色不会变成现任成员。迁移前的数据库复制为 `data/cubes.sqlite3.pre-team-backup.sqlite3`。

## 已实现

### 开始与团队

- 第一次打开会先见到负责人：给它起一个名字（默认「主管」，最多 64 个字，和成员名字一样不能与现有成员重名），再挑形状、身体颜色和眼睛颜色，右边就是它会用的样子。点「开始使用」后，侧栏、消息署名、聊天标题和所有提到它的句子都改用这个名字和样子（`POST /onboarding`，同时把 `meta` 里的 `onboarded` 置为 1 并推送 `workspace` 事件）。之后可以在「团队」里随时改名、换样子。已经在用的数据库不会看到这一步：只要里面有过消息、成员或群组，就按已完成处理。
- 主管可创建成员、建群、在群里发言、向成员分派任务，并把结果汇总回当前会话。用户也可以直接和任何成员对话，成员同样能调用工具包完成工作，回复末尾仍会带心情标签。
- 成员档案：成员编辑器按类别分栏（基本 / 模型 / 权限 / 行为 / 形象 / 档案 / 危险操作），档案那一栏里有回复次数、参与任务数和失败数、完成和进行中的任务、验收通过和打回次数、这段时间的用量、常用工具、记忆条数和最近参与的 5 次运行（`GET /agents/{id}/profile`）。主管每轮会在本轮消息末尾的 `<runtime>` 提示里看到一行简短的成员档案（最多 12 位、400 字），分派任务时可以参考；系统提示词保持不变，不影响前缀缓存。
- 「团队」面板实时显示每位机器人此刻在做什么：正在哪个会话、做到哪一步（点一下跳过去），排队的显示「排队」，空闲的显示上次回复是多久以前；头像跟着状态动。每一行右侧是它今天 / 本周 / 本月用掉的 token（`GET /usage?period=day|week|month`，按 `TIMEZONE` 切分）。每次模型调用——回复、上下文压缩摘要、记忆整理——都记到发起它的机器人名下（`model_usage` 表，第 13 版数据库迁移新增），群里接力时各算各的。
- 侧栏「更多 → 用量」（团队面板右上角的「查看用量」也能进）是用量面板：今天 / 本周 / 本月的总用量和与上一期的对比、输入与输出、缓存命中率、模型调用次数；一张按机器人分色堆叠的柱状图（今天按小时、本周按天、本月按日，悬停或聚焦看明细）；回复 / 上下文压缩 / 记忆整理各占多少；以及每位机器人的用量排行和预算进度（用到 80% 变黄，超了变红），点预算就地修改。
- 每位机器人可以设「用量预算」（每天 / 每周 / 每月多少万 token，带按周期给的常用档位，并实时显示当前用到了百分之几；在成员设置或用量面板里改，`PATCH /agents/{id}` 的 `token_budget`）。超出预算后，它下一次回复前先在会话里发一张卡片问你「继续」还是「停下」：继续则这次任务里不再问它，停下则任务以 `limited` 结束、不调用模型。定时任务在后台没人能确认，超出预算就直接停下。记忆整理只记账，不受预算限制。
- 主管可以删除成员：`delete_agent` 会先把行动挂起，等你点「删除」或「保留」才继续；删除后该成员的私聊和它参与的机器人私聊一起删除，群组里的历史发言保留，任务负责人置空。正在回复的成员会被拒绝，等它结束后再删。等待超过 `CONFIRM_TIMEOUT_SECONDS` 就按超时失败，停止任务等同保留。
- 机器人能改自己的名字和外观：`update_self` 接受 `name` 或一套外观（`shape` 加 `color`，可再加 `#rrggbb` 的 `eye`），校验和 `PATCH /agents/{id}` 完全一致——重名、「改了外观只给一半」、目录外的形状或颜色都会被拒绝，并把原因交回给它；主管还能用 `update_agent` 改任意成员（同样只限名字和外观，不能改职责和角色）。改完立刻推送 `workspace` 和 `sidebar` 事件，侧栏、头像和私聊标题一起更新，聊天里留一行「把名字改成了「X」」或「换上了新的样子」。
- 用户也能解散群组：`DELETE /conversations/{id}` 会删掉这个群组和它的聊天记录，成员、他们和你的私聊、笔记和任务都保留；正在回复的群组要等它结束，主管私聊和成员私聊不能解散。主管也可以调用 `dissolve_group` 提出解散，同样先挂起等你点「解散」或「保留」，但它在群里发言时不能在同一个群里发起解散。
- 成员外观（形状、身体颜色、眼睛颜色）存在后端，`PATCH /agents/{id}` 的 `appearance` 字段可以修改。表情不再由用户选择：回复的心情标签和当时的动作决定它，旧的 `expression` 字段仍会接收、校验然后丢弃。旧的 Blobatar 头像接口（`face.json` 和 PNG）保留给 iOS 端使用。
- 未读与「已完成」：侧栏每一行在机器人回了新消息、而你没打开过它时显示一个圆点；打开会话后前端把最后看到的 `seq` 上报（`POST /conversations/{id}/read`），圆点清掉。最近完成、还没被你打开过的运行列在侧栏底部的「已完成」里（最多 10 条，新的在前），点一条会跳到那个会话并定位到这次运行的最后一条消息。
- 团队导出 / 导入：「团队」面板右上角可以把整个团队存成一个 Markdown 文件（`GET /team/export`）：成员的名字、职责、外观、所选模型（只写模型服务名字和模型名）、工具权限、token 预算、停用的技能名，加上分组和成员关系、工作流图、技能名；**没有**聊天记录、记忆正文、API key、令牌或 Webhook 密钥。导入（`POST /team/import`）先预览会新建、改名（冲突加「（2）」）和本机缺失的技能，再点「应用」；默认不覆盖主管，勾选「覆盖主管设置」才会改它。

### 对话、群聊与消息

- 主管私聊置顶；主管创建的群组列在下面，每位成员还有自己的私聊。每个会话各自运行：不同会话可以同时跑任务，正在运行的那个会话里，输入框上方一行说明这条消息会怎么处理（见下一条），右边是停止按钮，不会把输入框锁住。
- 每个机器人和你之间只有一条对话：侧栏里一个机器人就是一行，点开就是它的聊天。它有自己的进度、停止按钮和侧栏圆点；右键成员可以编辑或删除，群组另有自己的行。
- 机器人在回复时你还能继续输入，发出去怎么处理是一个设置，不是发送时现选：「设置 → 团队」里的「机器人忙时你发的消息」给整个工作区定一个默认（默认「同时回复」），每位成员又能在成员设置里各自换一种，或者选「跟随团队设置」（默认）。同时回复让新消息在正在做的那条「工作线」旁边另开一条「回复线」：工作线不打断、不重来，回复线用只读工具（查资料、读文件、看进度板、`team_progress`）回答你的问题；要真做新活就调用 `start_task` 交给任务线排队。回复线的系统提示先教它分清「一句话」和「一件活」：真是写、改、做、跑、查一堆资料的活，第一步就 `start_task` 交出去，不要先自己读一圈文件、翻一遍记录再交——那些阅读属于任务线自己的线程，放在回复线里只会让任务卡片迟迟不出现；只有回答一个问题确实要看现成的东西时才做简短查阅，一轮最多 6 步（`start_task` 不算），用完就要求它收尾回答，再要别的工具会被拒绝并附一句「回答这一路只做简短查阅；要动手的活请用 start_task 交给任务线」。两条线互相看得见：回复线在系统提示里读到工作线真实的进度板（已完成 / 正在做 / 待办 / 最近三步），工作线在下一个模型调用边界收到一条背景说明（「群里刚才：用户问了…，某机器人回答了…」），用户追加的新要求则以「用户的新要求，请加进待办」的备注送到工作线。一个会话最多 4 条线，每个机器人最多 2 条（一条工作、一条回复），超出的消息排队；只读回复线不会写文件、跑会改东西的命令或操作电脑。用本机 CLI 引擎的机器人在两路同时跑时不安全：回复线改用备用模型或分发员模型（HTTP），两者都没有时排队。做完再发先排队，消息以「排队中」显示在输入框上方，可以撤回，这一轮结束后它作为新消息发送。停止并发送会停下正在写的回复，立刻回答新消息：机器人忙时 ⌘↵（Windows 上 Ctrl+Enter）就是这样发，输入框上方那行提示同时写明这条消息会怎么处理。群里按正在说话的那位成员的设置算，没人在说时用团队默认。`POST /conversations/{id}/runs` 的 `mode` 现在是 `parallel`（默认）、`queue`、`interrupt`：不传时按这位成员和团队设置决定，脚本要指定时照旧直接传；旧值 `steer` 迁移为 `parallel`。
- 机器人可以直接问你（`ask_user`，任何会话里的任何机器人都能用，私聊和工作流页面除外）：只在决定权真的在你手里时问——几个方案让你挑、要只有你知道的信息、要你确认一个会影响你本人的取舍时，它把问题停在会话里，这次任务就停在那里等你，没有超时。一次最多问 4 个问题，每个问题带一个短标签（如「方案」「时间」）和 2–4 个具体选项，机器人可以推荐其中一个（标「推荐」，默认选中）；每个问题的最后一行固定是「其他」，选中后可以自己写。问题以一行行动记录留在聊天里，同时出现在底部输入框的位置：有多个问题时顶部是可点的问题标签（答过的带对勾）和「下一个」；每个选项行前有数字键，单选选完自动进入下一题，多选用空格勾选、回车进入下一题，↑/↓ 移动，都答完点「提交」；「跳过」让它按自己的判断继续。答完这次任务从原处接着走，机器人拿到的就是每一题的答案；侧栏「等你的事」里也列成一条（显示第一个问题），标明「一直等到你回答，不会自己继续」。定时任务在后台跑、没有人能回答，调用会得到一句拒绝说明，让它自己决定。如果模型把话停在半句、没有调用 `ask_user`——回复以「：」结尾，或最后一句在宣告「需要你」「请你决定」「请选择」「确认一下」这类决定却没有开问题卡——后端会给它一次补问的机会：用同一轮再调一次模型，附一句「你的回复停在半句。要用户决定就调用 ask_user；否则把话说完。」，它的回答接在同一条回复后面，或换成问题卡；每次发言最多补一次，正常以「。」收尾的回复不会触发，本机 CLI 引擎不适用。
- 群组里用 `@名字` 点名（或通过接口传 `mentions`）时，被点名者按顺序真实回复，每人都看得到前面同事说了什么，像群聊一样接话、补充或反驳，说完就结束，不再由主管收尾。每次回复结束后会解析其中的 `@名字`，被点名且不在队列里的本群成员接着回复，一条消息最多 2 轮机器人之间的接力；到上限不再转交，改由最后说话的机器人（群里有主管时是主管）写一条收尾结论：已经定下什么、还需要你决定什么，用列表写清，不再 @ 任何人。哪个成员回答、要不要继续某件任务，由一个看不见的「分发员」决定：每条群消息在运行开始时多一次不带工具的小调用（`x-cubes-purpose: dispatch`，模型取团队设置 `dispatch_model`，没设就用备用模型或默认模型；一次最多 120 秒，等待期间你那条消息下的路由和运行状态都写「正在决定谁来接」；失败、超时或答不出可用 JSON 就按点名者、上一条机器人回复里被 @ 的成员、刚才被打断的成员、最后发言者、群里第一位成员依次兜底；模型支持推理档位时这次调用请求最低一档），它只输出一个 JSON：`answer`（谁回答，最多 3 人，可要求各自独立回答）、`steer`（这句话是对某件进行中/排队任务的补充）、`resume`（让某件停下/没做完的任务接着做）、`status`（问进度，直接发一张进度卡，不叫任何成员）或 `none`（「好的」「谢谢」这类不需要回应）。一条消息里有几件不同的事时，它还可以把消息拆成最多 6 项 `intents`：每项 `text` 是这一部分原话（不超过 60 字）、`kind` 按同样的几种（外加 `invite`）、`speakers` 最多 3 人、`task_id`、`invite`；各按原话顺序执行，每项在自己的回合里会收到一小段说明，告诉机器人这条消息里哪一部分交给它、其他部分交给了谁。分发员不在成员名单里、没有工具、不写任何聊天内容。分发失败（`TimeoutError`/`UpstreamError`/`Unreadable`）记在最近 50 条的小环里，`GET /settings/team` 的 `dispatch_health` 给出 24 小时失败次数、最后一次的类型和时间（设置页据此提示；24 小时里有失败时，「设置 → 团队」的「分发用的模型」下面多一行小字，写最近一次是超时、模型出错还是结果看不懂，以及时间）。用户明确点名的成员一定回答：开头 @ 的、从 @ 选择器里选的、以及被回复那条消息的作者；正文中间顺带提到某人通常只是引用，交给分发员判断。每条你发的群消息下面有一行小字写明这行由谁接手（`route`：`speakers`、`kind`、`task_id`、`reason`、`by`，`by` 是 `dispatcher`/`fallback`/`mention`/`user`；等待分发时多一个 `pending`；拆成多项时多一个 `intents`，每项写 `text`、`kind`、`speakers`、`task_id`、`invite`），点它可以重新选人（`POST /conversations/{id}/messages/{message_id}/reroute`）：正在回答这条消息的运行先按正常停止路径停下，然后用你选的人重新回答，不新写一条用户消息。有一项以上时，那行小字按顺序每项一行（邀请写「邀请 画师 → 画师」），超过 3 行先折叠成「还有 N 件」。等待分发时，那条消息下的提示写「正在决定谁来接」加三个动点，不再先写出名字。用户 @ 了不在群里的人、或机器人回复里 @ 了不在群里的人，不会悄悄消失：群里有主管时由主管先用 `set_group_members` 把人拉进来，说一句为什么，再由对方接手那一部分；群里没有主管时由后端直接加进群并发一行「已把 X 拉进群」；机器人 @ 的、群里又没有主管时只留一行「X 不在这个群里」和一个「拉进群」按钮（`POST /conversations/{id}/invite`，加人后让被邀请者回答那条 @ 它的消息）。机器人之间的邀请计入上面说的 2 轮接力上限。@ 选择器里也会列出不在群里的团队成员，单独隔一行「不在群里」。分发员也能把一句话并入正在做或排队的任务（`steer`），或让停下、没做完的任务从原处接着做（`resume`）；在任务线程里可以直接说「接着做」，也可以在群里说一句让分发员把消息 `resume` 到那件任务；「继续/接着做/continue」不再有独立的关键词判断。主管在群里默认只做组织：整理进度、检查结果、催办停住的任务、维护群规则和群记忆；`computer_shell`、`computer_browser`、`computer`、`run_code`、`file_write` 和会写工作台的 `note_create`/`note_update`/`note_delete`/`task_create`/`task_update` 不在它的工具列表里，读文件、搜索、记忆、`ask_user` 和团队管理仍可用；用户用 `@主管` 在开头点名的那一轮恢复完整工具，团队设置 `supervisor_works_in_groups`（默认 `false`，`PATCH /settings/team`）打开后整个工作区都不再受限。主管的私聊和单独对话不受影响。 成员名在工作区唯一（去空格、不区分大小写），重名创建或改名返回 409。
- 你也能自己建群或加成员：侧栏搜索框右边的 +（侧栏折叠时是第一格）弹出「新建群组…」和「新建成员机器人…」。新建群组可以先选一个模板（方案评审、项目推进、头脑风暴，会填好名称、目的和群规则），右边按名字和职责勾成员，没有合适的就在这里直接新建一位并自动选中；可选写第一条消息，建好后马上发到群里（`POST /conversations`，可带 `rules`），群里只留这一条创建者的开场，不会再让每位成员自我介绍；主管不再自动加进群，`include_supervisor: true` 才加，而且至少要有一位成员（空群返回 422）。群组设置里多了「群规则」（`PATCH /conversations/{id}` 的 `rules`，每位成员在这个群发言前都会读到，别的群看不到）和「群约定」：只在这个群里生效的记忆（`scope="group"`，`agent_id` 存群的 id），机器人在群里用 `remember` 的 `scope: "group"` 也能记；解散群时这些约定一起删掉。
- 消息里写了 `@所有人`（也认 `@everyone`、`@all`）时，群里的每位成员（包括碰巧在群里的主管）同时、各自独立回答，彼此看不到对方对这条消息的回答；不再另外安排主管收尾。除此之外，谁回答都由上一条说的分发员决定，群里没有「请谁依次回答」这类公开提示。
- 群任务：普通的群回复不再自动算任务——只有成员自己判断这件事要做几步、要花一会儿，调用 `start_task` 时才开一项任务（第 26 版数据库迁移新增 `group_tasks` 表；第 32 版起 `start_task` 和 `group_assign` 是唯一开任务的入口，旧数据库里没有线程的回复任务会被归档、不再续跑）。群聊标题栏右边有一个「群里的工作」小标签：有工作在做时写「2 项进行中」，有停下的写「1 项停下了」，都做完时只剩一个图标。点开是按你发的每条消息归在一起的列表：消息原文（去掉 @ 名字）、接手的成员和他们分出去的部分、各自状态，点消息或成员跳到对应的那条。任务状态是真实的：`queued`（排队）、`running`、`awaiting`（卡在等你确认/回答的卡片上）、`done`、`failed`、`stopped`；停下或失败的行带 `end_reason`（为什么：步数用完、模型服务失败、出错原因）和 `stopped_by`（谁停的：你、群里的某位成员、重启后中断）。卡片上的按钮：停下/失败的点「接着做」（`POST /conversations/{id}/tasks/{task_id}/resume`，在该任务自己的线程里继续）或「不做了」（`.../dismiss`，归档、卡片留在时间线里变灰）；做完的点开看过就标记已读（`.../seen`）。侧栏的群任务线程列表（工作区快照的 `group_threads`）里，停下的任务留到你点「不做了」，做完的留到你看过。成员可以用 `group_assign` 把自己任务的一部分交给群里另一位成员（对方在群里回答，结果交回来；每个请求最多分 8 次，每个群同时最多 2 个部分在做），或用 `group_transfer` 把整个任务转交出去（自己这一轮结束，对方接着回答）；这两个工具只在任务线程里提供。成员真正动手时在自己的任务线程里做：中间的短句、工具行和每一步都留在那里，群里只出现一张任务卡片（`kind="task"`、带 `task_id`，实时显示谁在做、做到哪一步、第几步）和最后一条结论（`reply_to_id` 指向你那条请求）。点卡片就是打开这条线程，你在线程里说的话会接着这件事做（算下一轮），线程有它自己的未读。任务表带 `thread_id`、`steps`、`current_step`、`awaiting_action_id` 和卡片消息 id，都随 `GET /conversations/{id}/tasks` 和 `group_tasks` 事件下发；线程是隐藏会话（`kind="thread"`），不列在侧栏和「已完成」里，群里只有最终结论和停下/失败的任务卡片会把会话标成未读。一次运行结束时，每个群只发一条 `group_work_done`，你不在那个群时提示一行「「方案小组」的工作结束了：完成 2 项」。私聊里也能开任务：机器人判断一句话答不完时同样调用 `start_task`，任务线程挂在这次私聊下面，任务卡片出现在私聊里（`kind="task"`，和群里同一张），默认排在它手上正在做的那条工作线后面，卡片写「排队中，等这一轮回复结束」（等的是聊天里另一个机器人时写「排队中，等「X」做完」）；卡片上有「现在就做」（`POST /conversations/{id}/tasks/{task_id}/now`），点了那条任务就在它自己的线程里立刻开始，不等手上那条（只放开这一位成员的并行限制，整个聊天的 4 条线、团队的同时任务数仍然算数）。主管在它的私聊里可以用 `start_task` 的 `owner` 把新活直接交给某位成员，任务归那位成员、卡片和结果也由它署名，不会排在主管自己那条线后面。私聊里的任务同样走 `GET /conversations/{id}/tasks` 和 `group_tasks` 事件。
- 机器人会自己判断要不要找同事、找谁、怎么找，不用你开口：只需要某一位同事的专长、一个具体事实或一次确认时，用 `direct_message` 私信那一位；开放问题、需要几个人的看法，或会影响几个人的决定时，用 `ask_group` 把问题带到自己所在的某个群里（只能是自己在的群）。问题以提问者的名义发到群里，群里除提问者外的每位成员依次回答、主管收尾，大家的回复作为工具结果交回提问者，提问者再用自己的话回答你，并说明问了谁；你在原来的对话里会看到一行「在『群名』里问了大家」，点开就是那个群。群里正有对话在进行时 `ask_group` 直接返回「群里正忙」，机器人改用私信或自己回答。私信和群里提问共用 2 层嵌套上限，一次回复最多找两次人。在群聊里则优先 `@名字` 当场问，不提供 `ask_group`。成员的提示里会列出它所在的群组。
- 成员回复按 Markdown 显示。助手正文直接落在底色上，不套白色卡片。输入栏浮在安全区上方。
- 复制和回复按钮只出现在每条回复的末尾，不会跟着中途的每一句走；复制带走这条回复里的全部文字（中途的几句话连同最后的结论），工具行和私聊来源标记不计入。
- 点「回复这条消息」会在输入框里出现一条引用（成员名加一行摘要），发出的消息带上 `reply_to_id`：气泡上方会显示「回复 名字：摘要」，点它可以跳回原消息；模型也会看到自己在回复哪条消息，群里还直接交给被引用的那位成员回答。按 Esc、点引用右侧的 ✕ 或发送成功后引用消失。机器人发出的回答如果在时间线上落在一个更新的问题后面（它答的是更早那条），回答气泡上方也会出现同样的一行「回复 你：摘要」，点了跳回它答的那个问题；紧接着回答、中间没有别的问题时不显示。已经结束、没有留下回答的活动小结（`activity-chip`）也一样，避免两个问题两个回答交错时分不清谁答的是哪句。
- 已经发出去的话可以改：在消息上右键（在单独对话和群组里才有这几项）。「编辑」只出现在你自己发的消息上，它把原文放回输入框，上方出现「正在编辑消息」的小条，Esc 或点 ✕ 取消并把原来的草稿放回去；回车发送后，这条消息和它后面的全部内容（回复、工具行、绑在这些消息上的图片、只在后半段存在的运行、覆盖后半段的摘要）一起被换掉，团队按改过的文本重新回答，文本里的 `@名字` 照常点名。「从这里重新开始」会先弹一张确认卡（这条留着，后面 N 条删掉，找不回来），确认后删掉这条消息之后的全部内容。会话正在运行、私聊旁观或工作流页面里，这两种操作会被拒绝并说明原因。删掉的东西同时从搜索、表情和摘要里消失；记忆保留正文，只去掉指向已删消息的来源引用；其他窗口靠 `message_removed` 和 `workspace` 事件跟着清掉。接口是 `POST /conversations/{id}/messages/{mid}/edit`、`/rewind`。
- 每条成员回复末尾由模型附一个心情标签（`neutral happy proud curious confused sorry surprised focused`）。后端在流式输出时把标签截掉，再存到消息的 `mood` 字段，客户端只看到正文。模型不按格式写也能认：`<mood>happy</mood>`、`<happy></happy>`、`<happy>happy</happy>`、`<happy/>`、带空格的 `< happy >…< /happy >`、结尾只写了一半没闭合的 `<happy>`，以及忘了尖括号、单独一行写成的 `@mood focused` 或 `mood: focused`（值必须是上面的心情之一）都算同一个心情；结尾的 `<images>…</images>` 和 `<answer>…</answer>` 不管排在心情标签前面还是后面都会去掉。正文中间提到的 `<neutral>`、代码里的 `List<int>` 和「今天的 mood 不错」这样的句子原样保留。第 11 版数据库迁移会把旧版本存下来的这些标签从回复里清掉，补上缺的心情，并把当时没认出来的转发图片挂回这条回复；第 14 版再跑一遍，清掉结尾残留的没闭合标签；第 17 版清掉结尾的 `@mood …` 行。较早一轮用过的工具会在历史里压成一行一条的备注，单独作为一条系统备注跟在那条回复后面，不拼进回复正文；模型照着抄出来的 `<此前用过的工具>…</此前用过的工具>` 一段也会从回复里去掉，第 12 版数据库迁移把旧回复里抄进去的这段清掉。
- 每条消息可以贴 emoji 表情：你可以给任意一条用户或机器人的消息贴表情，机器人也可以在回复末尾写 `<react>表情</react>` 标签，给它在回答的那条用户消息贴一个表情（不额外多一次模型调用，正文里看不到这个标签）。每个机器人对一条消息最多贴一个表情（再贴会替换），每条消息最多 20 个不同的表情。如果一条回复只剩表情、没有正文和图片，那条「正在生成」的行会被删掉、发出 `message_removed` 事件，任务照常完成；「好的」「谢谢」这类不用回答的消息，机器人可以只回一个表情。你给机器人的消息贴表情后，那个机器人会等 `REACTION_DEBOUNCE_SECONDS`（默认 2 秒，环境变量）再决定：不回应、回贴一个表情、或说一句很短的回复（一次小调用，记作 `purpose=reaction`）。
- 一次机器人的发言也是一条「活动」：从它开口到给出结论、停下或失败，期间每次工具调用和引出工具的那句话都算它的步骤（第 33 版数据库迁移新增 `activities` 表和 `messages.activity_id`；第 34 版新增 `runs.lane`、`activity_todos` 和 `activity_notes`；步骤数从消息行现算，不另存一份计数）。群聊里不再把一堆工具行摊在时间线上：进行中的活只留一张卡片（标题和现在在做哪一步，点开是完整记录），结束后只在结论上方留一行小结（「用了 N 步 · 40 秒」，停下或失败就写原因）。打开一条活动是按轮次分组的步骤：先是这位机器人自己，再是它问过的同事或开出的任务线程（`parent_id` 指回是谁引起的），每一步都能点开看原始的工具结果。机器人右键菜单里的「工作记录」列出它最近的所有活动（`GET /agents/{id}/activities?limit=&before=`，按 `started_at` 倒序分页；面板按今天 / 昨天 / 更早分组，滚到底自动读下一页，每行是状态图标、标题、摘要和时间），点一条打开详情（`GET /activities/{id}`：结论 `answer`、会话名和分组步骤 `sections`）。标题先取请求的开头 16 个字，第一次工具调用后（这一轮没调工具就在结束时）用分发模型再起一次不超过 20 秒的纯文本小调用，改成更像待办的短标题，结束时同一次调用再给一句 40 字以内的总结；这次调用记作 `purpose=activity-title`，失败就保留原来的标题和结论的第一句。运行中的活动靠 `activity` 事件更新（每秒最多一次，状态一变化立刻推），卡在等你确认或回答的卡片上时状态是 `awaiting`。
- 每条工作线先写一张进度板（`todo_write`，最多 12 条、每条最多 60 字，整张替换）：开工前写下要做的几步，做完一条就标 `done`，正在做的那条始终只有一条 `doing`。活动卡片和进度卡读同一张板（`todos`、`todo_done`、`todo_total`），回复线回答「做到哪了」时先看这张板，不靠记忆编；`team_progress` 只读地返回这个会话里每条进行中的工作和它们的板。活动详情还会列出别的线给这条工作留下的 `activity_notes`（`context` 是刚刚发生的事，`request` 是用户追加的要求）。聊天时间线里，同一轮写过的多张板收成一行「进度」：靠一个清单图标认出来，右边有和其他工具行一样的折叠箭头；折起来也写清在做什么——细进度条加「3/6」，下面一行是正在做的那条（还没有正在做就写「下一步：…」，都做完了写「全部完成」），点开、回车或空格展开全部条目（完成打勾变淡、正在做高亮、待办空心、不做划掉）。这一行留在这一轮第一张板写下的位置（开口就写板时正好在作者名下），后面的板只换这里的内容、不让行往下跳；数据优先取活动的实时板，没有就取 `todo_write` 行动自带的 `todos`（行动接口新增的字段：跑完读结果里的板，没跑完读这次调用写的参数），所以旧记录没有条目时退回原来那句摘要。群聊里这些行仍折进活动卡片，活动详情页顶部的「进度」块和这一行共用同一个清单组件。进度卡（「群里的进度」）上每条进行中的工作也用这一行：细进度条加「8/9」，下面一行「正在：…」，点一下展开全部条目，不再逐条排「已完成：…」「还没做：…」的长句。

### 权限、确认与文件

- 审批方式在「设置 → 权限」里选，三档：**手动审批**（默认）——在允许的文件夹里读文件直接做，写文件、运行代码、用电脑、连接器写操作、改定时任务、碰允许范围外的位置都先弹卡问你；**自动审批**——在允许的文件夹里读写、运行代码、用云端沙盒直接做，用这台 Mac、碰范围外的位置、连接器写操作和定时任务仍然问；**完全权限**——除了删成员和解散群组，什么都不问（选它要再确认一次）。每位成员可以在自己的「权限」里换一档，或者跟随团队（`PATCH /agents/{id}` 的 `permission_mode`，`null` 表示跟随；工作区的在 `GET`/`PATCH /settings/permissions`）。用 Claude Code / Codex 当引擎的机器人，CLI 自己的权限也按这一档开。
- 文件：相对路径落在工作文件夹（设了 `WORKSPACE_DIR` 就是它，否则是数据库旁边的 `workspace/`，一定存在），`~/Downloads/方案.md` 这种完整路径也认。「设置 → 权限」里可以再加几个文件夹（最多 20 个），在里面就算「允许的文件夹」。Cubes 自己的数据目录（里面有模型密钥）不管哪一档都读写不了。
- 确认卡上有三个按钮：同意、拒绝，以及「总是允许」——点了以后，这位机器人的这种操作不再问你；文件卡记住的范围和卡上说的一样窄（「在允许的文件夹里写文件」不会顺带放开范围外的位置）。规则在「设置 → 权限」里列着，可以随时删掉（删掉后下一张卡又会出现）。定时任务在后台找不到人确认，原本会拒绝；先为这个操作建好「总是允许」规则，它就能照常执行。
- 侧栏在会话列表上面列出还在等你的事：确认卡，以及工作流停下来问你的那一步。每一行是谁、在哪个会话、在问什么、不答会怎样；点进去打开那个会话并跳到那一条，按钮还在原处。确认卡默认 10 分钟不答就按没同意处理（删成员和解散群是保留，超预算是停下，沙盒是这次不用，工作流的「先问我」是暂停这一步）。工作流的问题没有超时，会一直等。
- 按成员分配权限：成员设置里的「权限」可以单独关掉运行代码、读写文件、沙盒电脑，连接器可设全部 / 只读 / 不能用（`PATCH /agents/{id}` 的 `tool_permissions`，`null` 表示全部允许）。关掉的工具不会出现在这位成员的工具列表里，强行调用也会被拒绝；这些开关决定它有没有这种能力，审批方式决定用的时候问不问你。

### 输入、附件与上下文

- 输入框浮在消息上面，是一张毛玻璃卡片，消息从它后面滚过去；卡片的上沿就是一条很细的上下文容量线，按模型真实窗口显示这次请求会用掉多少（系统提示词、记忆、技能、工具定义、你的消息、机器人回复、工具调用、工具结果、摘要，估算方式和真正发请求时一样）；鼠标停上去会变粗并显示「上下文 56% · 还剩 293K 后自动压缩」，颜色在 60% 变黄、到自动压缩阈值变红。输入框左边的 + 可以加图片（自动缩到 2048px、5 MB 以内）、PDF 和文本/代码文件（20 MB 以内，一条消息最多 4 个附件），也可以粘贴或拖进来：图片在输入框上方显示缩略图，PDF 和文本显示文件名、类型和大小，上传时转圈、可单独移除；消息里图片照旧排成网格，文件是下面的芯片，点一下用新窗口打开（文本和 PDF 从本地 blob 打开），窗口被拒时按原文件名下载。回答的模型看不到图片、或读不到 PDF 时，输入框下面会有一行说明它只能看到文件名。点开是完整的去向面板：一个大数字、按类别分色的堆叠条（右端斜纹是自动压缩缓冲，竖线标出阈值）、每个类别和每种工具各占多少，以及「立即压缩」——压缩时条上有斜纹动画，完成后显示「已压缩：48K → 12K」几秒。
- 每条消息最多带 4 个附件，三种：图片（PNG/JPEG/WebP/GIF，客户端会先压到 5 MB 内，主要用来贴截图）、PDF（20 MB 内）、文本文件（代码、Markdown、CSV、JSON 等，UTF-8，20 MB 内）。类型由后端看文件的字节本身决定，不信客户端声明的 Content-Type；文件名通过 `X-Attachment-Name` 头（`encodeURIComponent` 过的原文）传来，后端只留文件名本身、去掉控制字符、最多 120 字，`GET /attachments/{id}` 用 `Content-Disposition` 把它带回去。图片以外的东西是「文件」：聊天气泡里显示文件名和大小，点开用对应程序打开。
- 附件到模型那里分三种走法。图片还是原样：能看图的模型收到最新 4 张的像素，更早的只有 `[图片 att_…]` 标签；不能看图的模型只有标签，好让机器人还能把 id 转给别人。文本文件对每个模型都直接内联成一段文字：先一行带文件名和 id 的标签，再用 `<<<文件内容` / `文件内容>>>` 围起来，单个文件最多 4 万字（`TEXT_FILE_CHARS`），超出的部分换成一句「文件过长，已截断：共 N 字符，这里只显示前 4 万字」。PDF 给「能读 PDF」的模型：最新 2 个作为 `file` 内容块（`data:application/pdf;base64,…`，Anthropic 协议转成 `document` 块）随请求发过去，更早的只剩标签；模型不能读 PDF 时标签直接写「这里读不到内容」。预算估算里 PDF 按大小折算 token（每 64 字节约 1 token，最少 1500、最多 60000），不是免费。
- 模型想得久时不会像卡住：还没出字之前，发言人旁边每 5 秒更新「正在思考（N 秒）」或「正在等模型回复（N 秒）」。连续 90 秒什么都收不到（没有正文、没有思考、没有工具参数）的回复，或者模型服务中途断开连接的回复，只要还没有字显示出来，就会被放弃并自动重试一次，再不行就以这个原因结束任务；已经显示了一部分的回复不重试，免得说两遍。模型服务直接拒绝这次请求（HTTP 5xx 或 429）时，隔 1 秒、3 秒各重试一次；4xx 等其他错误不重试。
- 上下文按模型的真实窗口管理：每个模型的能力自动探测，先看你为它填的值，再看服务商 `GET /models` 自己的说明（图像/视频/音频、窗口、输出上限、是否思考），再查随包携带、每天在后台更新到数据目录的 models.dev 目录，都没有才用 `CONTEXT_WINDOW_DEFAULT`（128000）和 `CONTEXT_OUTPUT_DEFAULT`（8192）。「设置 → 模型」里每个模型都显示「图片 / 视频 / 音频 / 1M / 输出 64K / 思考」这些标签，悬停能看到是谁给的答案；查错了就点「看图 / 不看图」改掉（标「手动」），「调整」可以手填窗口和输出上限，两项留空就回到自动。一次请求能用的额度是「窗口 − min(输出上限, 20000) − 8000」。估算走到额度的 90%（`COMPACT_PERCENT`，输入框边框上容量线的阈值也是这一个数；128K 窗口约在 90K 时压缩）时，较早的对话会被折进这个会话自己的一条中文摘要（进展、决定、约束、未完成的事、之后要用的事实），最近的若干轮原样保留：128K 窗口 7 轮、更宽的窗口放大到最多 24 轮，私聊是 4 → 12 轮；再压一次时把新内容合并进旧摘要，只往前推、不倒退。摘要由这个 bot 自己的模型写（不带工具，正文限 3000 字，输出上限 4000 token，给会思考的模型留出余量；被长度截断时保留已写出的部分），写作失败不影响任务：这次改为从最早的消息开始裁剪，绝不因为上下文太长而失败。压缩发生在发起一轮回复前，也会在一次回复结束、会话已经超过阈值时立刻补一次（不等下一轮把压力带过来），两者都不改聊天记录。backend 推 `context` 事件（`state` 为 `compacting` 或 `idle`，带 `auto`，完成时带 `before`/`after`），打开着的输入框因此实时显示「正在自动压缩…」或「已自动压缩：48K → 12K」，不需要轮询。
- 上一轮的工具调用不再凭空消失：会把最近几次发起过工具的回复按原生的 `assistant.tool_calls` + `tool` 结果重放，每条结果按「开头三分之二 + 结尾三分之一」截断并注明原始长度；能放多少随模型窗口走——128K 窗口重放最近 3 次、共 8000 字（每条最多 2600 字），512K 窗口 6 次、共 32K 字，1M 窗口 12 次、共 60K 字（每条最多 8000 字），从最新的结果往前分；更早的回复压成一行「调用了什么、结果如何」，放在那条回复的正文后面（这一行的长度也随窗口放大，128K 是 200 字、宽窗口 400 字）。工具结果本身的截断也改成保留头尾，终端命令的报错和堆栈不再被切掉。截图按标签分别保留最新几张像素（沙盒屏幕 2 张、浏览器 1 张），并且是在整条组装好的请求上裁剪，跨轮也生效。
- 队友做的事不再隐形：别的机器人这一轮实际执行过的工具动作（写了哪个文件、跑了什么命令、结果如何）会以一行一条的备注跟在它那条回复后面，整次请求的花费有上限（128K 窗口 2000 字、宽窗口最多 12000 字，从最新的往前分）。一个群里的下一位机器人因此知道文件已经被谁改成什么样，而不是只看到一句「改好了」。
- 每个会话有一个**工作集**：任何机器人 `file_write` / `file_read` 过的文件（以及终端里 `cat`、`sed -n`、`grep`、`sed -i`、`tee`、`> 重定向`，和 `python3 - <<EOF … write_text(…)` 这类脚本改的文件）都会记进 `working_files` 表，一个路径一行，最新的那次覆盖它：谁、写的还是读的、几行、当时多大、差异 +/- 多少、什么时候。下一次请求的运行提示里列出这个会话最近 20 个文件（最新在前），最新的几个小文件还会附上**现在从磁盘读出来的**内容（最多 3 个、合计 4000 字符），所以机器人不用再读一遍就能接着改。文件被删了、之后又被别人改动过、或者不在允许的文件夹里，都会当场标出来，不会给过期的内容。
- 摘要不再把干过的活丢掉：压缩时给摘要模型的记录里，每个机器人的发言后面都跟着它这一轮的工具动作（路径、命令、结果），摘要提示词也要求保留真实文件路径、每个产物现在是什么状态、跑过的命令结论和还没解决的问题；摘要上限从 1200 字提到 3000 字，压缩时留下的原文轮数也随窗口从 6 轮放大到最多 24 轮（单聊 4 → 12）。
- 前缀缓存友好：系统提示词和工具列表在团队、群组和连接器不变时逐字节相同——时间、沙盒状态和已连接的外部服务这些每轮都在变的东西，统一挪到这一轮最后一条用户消息末尾的 `<runtime time="…" timezone="…"/>`（以及它前面的提示行）里。Anthropic 请求的 `system` 改成带 `cache_control: ephemeral` 的内容块，并在最新一轮之前的那条消息上打第二个断点。每次模型调用都会请求并记录 `usage`：`runs` 上的 `input_tokens`、`output_tokens`、`cached_tokens` 是这次任务所有调用之和，`compactions` 是压缩了几次。
- 工具调用步数默认**不设上限**：一轮发言（连同它中途的工具调用）一直做到模型不再要求调用工具为止，和别的 agent 产品一样，不会再在第 32 步被截断。上下文不是靠步数控制，而是照旧按模型窗口管理：每一轮开始时把较早的对话折成摘要，单轮跑得很长时按「工具调用和结果一起丢」的规则裁剪到放得下，所以长任务不会因为步数多而失败。真正的护栏是用户随时可以「停止」、每位机器人可选的 token 预算，以及沙盒电脑自己的上限（它也随档位走：默认档没有上限，标准档 40 步、其中终端 30、浏览器 25、屏幕 8，宽松和很长按同样形状放大）。要控成本的话，「设置 → 团队 → 每次能做多少步」仍可选一个有限档：**标准**（每位机器人每次发言 24 次模型调用、32 次工具调用，整次任务 64 / 128，由 `MAX_MODEL_CALLS_PER_TURN`、`MAX_TOOL_CALLS_PER_TURN`、`MAX_MODEL_CALLS_PER_RUN`、`MAX_TOOL_CALLS_PER_RUN` 决定，环境变量照旧可以改）、**宽松**（64 / 96，整次任务 192 / 384）、**很长**（160 / 256，整次任务 400 / 800）；工作流的预算跟着整次任务的数按原来的比例放大（模型 2.5 倍、工具 2 倍，不低于 160 / 256）。群里接力时后面的成员不会被前面的用光额度。有限档到了上限才以 `limited` 结束。到上限时聊天里留一行安静的系统提示，写明先到上限的是哪一项：「「某某」的沙盒屏幕操作用到了 8 步的上限，先停在这里。发「继续」接着做。」（模型调用、工具调用、整个任务的上限说法相同；一轮被截断时是「「某某」这一轮用了 N 步，先停在这里。发「继续」接着做。」）。私信里发「继续」会告诉机器人这是接着上一次没做完的工作，从上次停下的地方接着做，已经做完的不重做。一轮的预算用完时，多出来的调用不执行并告诉模型「用完了」，它再写一次回复、用已经查到的内容收尾；这次收尾里还要工具，就**只结束这一轮**——已经写的回复留下，整次任务照常继续。所以私信、咨询、工作流的某一步里对方那一轮被截断时，外层不会跟着失败；结果里会写明「这一轮的调用预算用完了」，而不是当成对方没回复。

### 记忆、技能与工作台

- 主管和成员共用一套工具包（`backend/app/toolkit/`）：上网搜索与读网页、翻自己的历史与读取会话、团队笔记和任务（含 `note_delete`，笔记删掉就不能恢复）、时间与精确计算与单位换算；还能列目录、读写文件和跑一小段 Python 或 shell，用之前问不问你由审批方式决定。每次调用都以行动记录出现在会话里；搜索、读网页和各类工具还会留下给用户看的详情，点开行动记录就能看到真实的搜索词、搜索服务、结果标题与摘要，或读到的网页和算式结果。
- 一件能拆开的事可以同时做：任何机器人都能用 `run_subtasks` 把它分成最多 5 个彼此独立的小任务，每个是一次专注的尝试（同一身份、同样的工具，去掉 `run_subtasks` 本身，不能无限递归），各有自己的一小份预算（这一轮最多 6 次模型调用、4 次工具调用），真的同时跑。结果作为一条工具结果一起交回来，由它汇总成最终回答；聊天里只留一行「并行做小任务」，展开是每个小任务的标题和状态（进行中 / 完成 / 没成功），每完成一个就实时更新。停止任务会把所有小任务一起取消。
- 工作台里可以直接动手：笔记详情右上角可以删除笔记（先确认再删）；任务每行有完成的勾选和状态菜单，标成已完成后会立刻挪进「已完成」，改动在所有窗口之间实时同步。
- 长期记忆：关于用户的偏好、每位机器人自己的经验、团队决定各存一条成句的事实，放在本地 SQLite 的 `memories` 表里，用双字切分的全文索引检索，所以「咖啡」能命中「我每天早上喝咖啡」。机器人用 `remember`、`recall_memory`、`forget` 读写，说「记住……」也一样；每次回复的系统提示里带一段 `<memory>`（关于用户 / 你的经验 / 团队决定，钉住的排在前面，超出 `core_chars` 只整行丢弃并写明还有几条可查），并按这轮用户的话自动补最多 3 条相关记忆。一次运行完成、可见且没有暂停时，这一轮排进所在会话的待整理队列——用户只回了「好的 / 谢谢 / 嗯」这类确认、或这一轮机器人已经自己调用过 `remember`/`forget` 的不排；会话安静 2 分钟（`MEMORY_IDLE_SECONDS`）或攒满 5 轮（`MEMORY_BATCH_TURNS`）后，一次模型调用把这些轮次一起静默整理成记忆（队列存在数据库里，重启后照常整理，「记住了 N 条」挂在这一批最后一条回复下）：整理时能看到和这几轮话题相关的条目以及最新的其他条目（最多 12 条），同一件事换了说法也会更新原条目而不是再记一遍，旧条目留在历史里（同一运行只整理一次，失败只留一条错误记录、不会积压）；机器人私聊与定时任务的后台会话永不读写记忆。侧栏「记忆」面板能看到全部条目（含被替换、被忘记的旧条目）、改正文、钉住、删除，也可以整体暂停或关掉自动整理，改动实时推送 `memories` 事件；回复下面的「记住了 N 条」能直接看到这轮记下了什么、当场删掉。
- 技能（Agent Skills）：一套可复用的做法（`<名称>/SKILL.md`，YAML frontmatter + Markdown 正文，可带 `scripts/`、`references/`、`assets/` 文件）存在后端 `skills` 表和第 16 版迁移里，每个技能一个文件夹（0700，文件 0600）。侧栏「技能」面板里可以从本机导入（Claude Code、Codex 等应用已经装好的技能：`~/.claude/skills`、`~/.codex/skills`、`~/.agents/skills`、`~/.cursor/skills`、`~/.gemini/skills`、`~/.omp/agent/skills`，拷一份进来）、自己写、上传 zip 或单个 SKILL.md、从 GitHub 仓库/路径导入（`GET`/`POST /skills/local`、`POST /skills`、`POST /skills/upload`、`POST /skills/github`）；导入和上传的技能先停用，看过内容后再启用。有可用技能的机器人，系统提示里会带一段 `<skills>`（一行一个 `- 名称：说明`，加上使用规则和安全边界，字节稳定），遇到对应任务先用 `use_skill` 读做法、`read_skill_file` 读其中的文件、`skill_create` 自己写一套做法（写完等你在「技能」里启用）；带脚本的技能用 `skill_to_computer` 放进沙盒电脑（走和沙盒工具一样的允许卡片和单持有者）后，再用 `computer_shell` 运行脚本。每位成员可以在「权限」里按技能单独关掉（`tool_permissions.skills_disabled`），改动实时推送 `skills` 事件。

### 工作流、定时与 Webhook

- 工作流是一张图：节点做事情、连线决定先后，机器人写、你也能改，一次运行开在它自己的页面上按依赖跑完（参考私聊：页面归负责它的那位机器人，侧栏不列，从聊天里那行入口进去）。往前走的连线不能成环（成环就没有终点）；要重复做，就画一条连回前面节点的「循环」线，并写上最多循环几轮。每个机器人管自己的（主管能管所有人的）：`workflow_create`、`workflow_update`、`workflow_delete`、`workflow_list`、`workflow_read`、`workflow_run` 六个工具，删除或修改别人的会被拒绝并说明原因。机器人写好的工作流默认就是**启用**的，写完可以直接运行；要停用就让它自己或主管调 `workflow_update`（`enabled: false`），也可以在侧栏「工作流」里关掉——主管能开关任何人的工作流，成员只能开关自己的。停用的工作流 `workflow_run` 直接拒绝。
- 节点有三种：`do` 交给自己按指令干活（工具照常可用），`ask_user` 把指令当成问题发出来、停下来等你回答（这一步不花模型调用，你的回答就是它的产出），`branch` 让你在 `choices` 里选一条路。连线里只有分支节点的边带 `when`（属于哪个选项）。每个节点还能设 `gate: confirm`（开始前先弹一张卡问你）、`on_fail: stop/retry/skip`（失败时停下、重试一次或跳过）。只给 `steps` 不给 `edges` 时按顺序连成一条线，所以「一串步骤」仍然是合法的工作流。
- 推进由引擎负责，不是模型自己记进度：引擎算「前沿」——所有父节点都已结束、且入边确实被走过的节点——按计划顺序一起开跑（同时最多 4 个，`MAX_PARALLEL_STEPS`）。分支只走被选中的那条边，另一支上够不着的节点标成「已跳过」（不是悄悄忽略）；汇合点要等所有父节点都结束，只要有一条入边是活的就跑。节点状态按节点 id 存（`workflow_steps.node_id`），所以面板里拖动、插入节点都不会把跑了一半的走弄乱。
- 并行：一个扇出的几条支路会同时跑，不再一个接一个。引擎按计划顺序把能跑的节点一起开出去，最多 4 个（`MAX_PARALLEL_STEPS`；一边跑一边有空位就补下一个），每条支路是一次独立的对话轮次，所以左支路还在等模型时右支路的答案已经在页面上往外写了——两条都显示「进行中」，流转图上各自的入线都在流动。超出上限、还在等空位的节点写「排队」，走不到的仍是「未开始」。每个节点只做自己的事，提示里告诉它同时进行的是别的分支、不要替它们做；对话里每条回复照旧按节点归属（`workflow_steps.message_id`），所以两条回复交错出现也不会串。汇合要等所有父节点结束；`ask_user` 或 `confirm` 卡只停住它自己那一步，旁边的支路照常跑完，等没有别的活可干时才停下来等你（同一个页面一次只问一个问题，第二个 `ask_user` 排到回答之后）。模型和工具的调用上限算整次运行的（`MAX_WORKFLOW_MODEL_CALLS_PER_RUN` 等），不是每条支路各一份。按暂停时正在跑的支路会跑完当前这一步再停，不再开新的；按停止则所有支路一起取消。不同工作流各有各的页面，互不排队。
- 循环：一条带 `max_loops`（1–20）的连线从后面的节点连回前面的节点，例如分支「审稿」的「不合格」连回「写稿」并设 3 轮。走这条线时，引擎把它的终点和终点后面所有的节点（只算往前走的连线能到的）放回「未开始」，计一轮，然后从终点重新往下跑；上一轮每个节点的产出、选择和消息存进它的 `history`，节点的 `round` 加一，对话里那几条消息仍然带着「第 N 步 · 标题 · 第 K 轮」的标签。重新跑的节点会被告知这是第几轮、要在上一轮的基础上改进。轮数用完后这条线失效：从分支出去的，那个选项不再提供给模型（提示里写明它已到上限），模型硬要选它也不算，分支按「没有给出可用的选项」结束；从普通节点出去的，流程直接走它的其他出线。循环线不是依赖，节点不会等它；每次运行的轮数记在 `workflow_runs.loops`（`{"from->to#when": 次数}`），重启后照样接着数。不带 `max_loops` 却绕回去的连线、或者带了 `max_loops` 却没有绕回去的连线都会被拒绝并说明原因。整个运行仍受 `MAX_WORKFLOW_MODEL_CALLS_PER_RUN`（默认 160）约束，循环再多也跑不出这个上限。分支的答案按「完全等于某个选项 → 最先出现的选项 → 同一位置取最长的那个」来认，所以「不合格」不会被当成「合格」。
- 游标和节点状态都在库里，每步是一次独立的有界对话（每步重新拿一份这一轮的调用预算），所以暂停、跳过、重跑、重启之后都能从原处接着走。服务重启时，跑了一半的工作流标成「已暂停」，不会像普通任务那样直接失败；停在问题上的那次保持「等你回答」。
- 每次运行有自己的页面（会话类型 `workflow`，标题「工作流 · 名字」，成员只有负责它的那位机器人）：每一步的结论、`ask_user` 的问题、`confirm` 卡都是这位机器人在这个页面里的普通消息。聊天里只留一行入口，带实时状态（进行中 / 等你回答 / 已暂停）和最终结果（跑完了 n/m、失败原因、已停止），点它进入页面。这一行不是你说的话，也不会进模型的上下文：从聊天里调用 `workflow_run` 时就是那一条工具行本身（不会重复出现两行），从「工作流」面板点「运行」时由后端在负责人的聊天里补一行。
- `workflow_run` 是**交接**：机器人调用它之后，这一轮就结束了——不会接着自己搜索、读网页，也不会去私信成员替工作流干活；它已经写下的那句话保留，真正的每一步在那个页面里由负责它的机器人做。想让它先交代一句再开工，就在同一次回复里说完再调用。
- 页面右侧浮着一张流转浮窗（不是并排的面板，浮在对话上面，对话给它留出右边的空档）：收起时只有一行——名字、「3/6 步 · 进行中」和状态灯，点它展开；展开时上半是简化版画布——节点按依赖层次摆开、连线上带箭头、循环线是橙色虚线，每个节点按状态上色（已完成、正在做并呼吸、等你回答、失败、已跳过/未开始），打开时节点按顺序逐个浮现、状态一变轻轻弹一下、正在走的每条连线上都有一段流动的虚线、等你回答的节点慢慢呼吸，系统开启「减少动态效果」时这些都直接到位；点节点在下面看它的标题、状态、产出，还能重跑或跳过这一步；再往下是暂停、继续、停止、这一步的问题输入框，底下一行「正在做：标题」（几条支路同时在跑时是「正在并行：标题、标题」）。这一步在做、还没吐出第一个字的时候，对话里有一行「正在做第 N 步「标题」…」，排队时是「正在排队，马上开始…」，等你回答时是「等你回答…」。
- 在页面里发的消息：工作流停在 `ask_user` 的问题上时，它就是这个问题的回答（输入框提示会变成「回答这一步的问题」）；其他时候它是一条普通消息，会打断正在跑的那几步，工作流因此停在原处（暂停），按条上的「继续」从这几步重新接着跑。`POST /workflow-runs/{id}/answer` 与在输入框里回答等价。定义在「工作流」面板里改，面板分三栏：左边是按所有者分组的列表（可搜索，能收起），中间是画布，右边是检查器（什么都没选时是工作流本身：说明、版本、运行记录、复制成 `WORKFLOW.md`、删除；选中节点时是这个节点的类型、标题、指令、分支选项、开始前确认和失败处理；选中连线时是它连着谁，循环线还能用 − / + 改最多几轮）。名字、启用开关、保存和「运行」在顶栏；有没保存的修改时「运行」变成「保存并运行」，切走或新建前会先问要不要放弃。画布可以无限拖动：拖空白处平移，触控板捏合或 ⌘ + 滚轮以指针为中心缩放（25%–200%），⌘0 或点缩放比例适应画面（不会放大到 100% 以上，比画面还大的图从左上角的入口开始显示）。节点可以拖动摆位置（对齐 8px 网格，位置存在节点的 `x`/`y` 里）；从节点底部的圆点拖到另一个节点就连出一条线，分支节点每个选项各有一个圆点，从哪个圆点拖出去这条线就属于哪个选项；拖回一个已经能走到这里的前面节点时，拖动中的线就变成循环的颜色和走法，松手后是一条默认 3 轮的循环线，并自动选中它方便改轮数；连到自己、重复连线、一个选项连两次会当场拒绝并说明原因。循环线是橙色虚线，绕到它跨过的所有卡片的右侧再从上方进入终点，线上有一个小标签写着最多几轮（运行后是「已绕/上限」）。点连线选中后按 Delete 或点它中间的 × 删除，选中节点按 Delete 删除节点；双击空白处加节点，工具条的「节点」把新节点放在选中节点下面并连好。「整理」按依赖层（不算循环线）从上往下重新摆一遍，分支的两支落在各自选项的下方。
- 画布的动画都在说明刚发生了什么：打开工作流时卡片按层从上往下依次浮现、连线从端口画到目标，箭头在线画到时落下；缩放、⌘0 和「整理」都是平滑过渡（缩放按比例插值，25% 到 100% 和 100% 到 200% 一样均匀），「整理」时每张卡片从原处移到新位置；新卡片弹入，删掉的卡片和连线淡出；拖动中的卡片稍微抬起并倾斜，静止的卡片悬停时只加深阴影、不放大，所以连线始终接在端口上；拉线时线是流动的虚线，所有能连的入口圆点会呼吸，吸附到卡片上时线变实；连上了目标卡片会扩散一圈光环，被拒绝（连到自己、重复）时卡片左右晃一下并弹出原因。箭头是每条线自己画的小三角，颜色跟着线的状态走（悬停、走过、没走、选中），尖端正好落在目标卡片顶部的实心入口点上。运行中的节点光环呼吸，从它出去的连线上有光点往下流，等你回答的节点图标会轻轻摆动。系统开启「减少动态效果」时这些都直接到位，光点静止。
- 在桌面版里，工作流面板顶部那一行（左边搜索框那行、右边名字和按钮那行）的空白处可以拖动窗口，按钮、输入框和开关照常点击；名字输入框只有文字那么宽，余下的空白都能拖。
- 定时任务：主管用 `schedule_create`、`schedule_update`、`schedule_list`、`schedule_delete` 在指定会话里按规则安排工作，规则三选一：一次（`at`，本地时间）、按间隔（`every_minutes`，最少 5 分钟）、cron（5 段表达式），都按 `TIMEZONE` 解释，最多 20 个启用；也可以在侧栏「定时」里自己建和改。到点时团队在后台、你看不到的地方（这个任务自己的隐藏会话）去做：目标会话里不出现触发消息，也不显示中间的说明和步骤；做完由建这个任务的机器人（你自己建的就是主管）在会话里发一小段标着「定时任务「名称」」的总结，出错或到上限则发一句没做完的原因，中途被停止就什么都不发。「定时」面板里，正在做的任务会显示「进行中」和它此刻在做的那一步（每秒最多刷新一次），可以随时「停止」；「运行详情」打开最近一次运行的完整过程：指令、每一步工具调用和回复，正在进行时会自动刷新。后台运行从不占用你的会话：你可以照常在同一会话里聊天，两边互不打断，它也不出现在工作区的「正在运行」里。没预先允许沙盒电脑的任务第一次要用时，建这个任务的机器人会在目标会话里发一张「允许 / 拒绝」卡片，运行等你回答（最多 `CONFIRM_TIMEOUT_SECONDS`）：允许后这次接着做，并且这个任务以后到点都直接用；拒绝或超时则这次不用沙盒、改用别的办法；停止任务时卡片一起作废。其他需要你确认的步骤（删除成员、解散群组、会改数据的连接器）在后台没有人能确认，会被直接拒绝，任务改用别的办法做。上一次触发还没结束时这次先排队，前一个一结束立刻开始。后端停机期间错过的触发不会补跑：重复规则直接跳到下一个时间点，一次性的标记为 missed 并停用。任务可以预先允许用沙盒电脑（到点后不再弹允许卡片），但由它发起的运行里不再提供这些管理工具，避免递归。建、改、删都会先挂起等你点「创建」「保存」「删除」或「取消」；删除任务时，它在后台留下的记录一并删掉。
- 提醒：任何机器人都能用 `remind_me` 给自己设一个提醒（`in_minutes` 多少分钟后，或 `at` 本地时间，加一句 `note`），用 `cancel_reminder` 取消；每个机器人最多同时留 20 个。到点后它在**原来那个会话里**被重新唤起，聊天里先出现一行安静的「提醒：{note}」，然后它接着做事或说话。提醒是 `kind="reminder"` 的一次性定时任务，列在「定时任务」面板的「提醒」标题下，可以在那里取消。
- Webhook：定时任务和工作流都能有一个自己的密钥网址（一个目标一个，在「定时」的编辑卡或「工作流」的检查器里创建）。网址是 `POST /hooks/{id}`，调用时带 `Authorization: Bearer <密钥>`（也可以 `?token=<密钥>`），就会立刻跑一次：定时任务用它自己的指令，工作流把它当成这次的输入。请求体可选，JSON `{"input": "…"}` 或纯文本都行，最长 64 KB；定时任务会把这段输入接在自己的指令下面，工作流直接拿它当 `input`。成功返回 202 和这次运行的 id（定时任务的上一次还没跑完时会排队，返回 `status: "queued"` 和 `run_id: null`）；密钥不对 401，同一个 Webhook 5 秒内再调 429（带 `Retry-After`），停用 409，目标已经删掉 404。密钥是 32 字节随机串，数据库只存它的 SHA-256，只在创建或轮换的那一次显示出来，页面让你当场复制（还有一键复制 curl 示例）；「轮换密钥」让旧密钥立刻失效、网址不变，「删除」之后这个网址 404。`/hooks/` 是唯一不走桌面启动令牌的路径，它自己的密钥就是全部凭据；创建、轮换、删除这些管理接口照旧要启动令牌。桌面版的后端只绑 `127.0.0.1`，要让外面的服务打得到，得按「部署到服务器」用反向代理把它露出来。

### 模型、外观与电脑

- 模型服务在「设置 → 模型」里管理：可以存多套 OpenAI 兼容或 Anthropic Messages 服务，读模型列表、测试连接、选默认模型，还能给每个 bot 单独指定模型（主管同样适用）；也可以直接用本机已登录的 Claude Code 或 Codex 订阅当引擎，不需要 API key；还能选一个工作区级别的备用模型，主模型连不上、被限流或额度用完时这次回复自动换它重试一次，并在聊天里留一条系统提示；原来的服务或模型被删掉时，bot 自动回到默认模型，编辑器里也会提示。API key 明文存在本地 SQLite（0600），永远不出现在接口、事件和日志里。
- 浅色、深色、跟随系统三种外观，外加六个主题色（矿石蓝、紫罗兰、松石绿、琥珀、玫红、青碧）和「自定义」：在「设置 → 常规」里选，也可以自己挑任意颜色，跟着窗口一起记住。自己挑的颜色里，气泡配的字自动适应：浅色（比如浅黄）原样用它、配深色字；饱和一点的颜色配白字，气泡会为了白字稍微调深一点（黑字在那种底色上只有微弱优势，看着发闷）。压在气泡上的字（表情贴纸、提到的人名）同色系一起变。选中气泡里的文字时，高亮按字的颜色混出来，一眼能看见。用作线条、图标和按钮的那一份会往深或往浅调，直到在页面上的对比度达到 4.6:1，所以浅黄这类颜色排版出来是深橄榄色的强调线，而不是看不清的浅黄。主题色同时决定界面里的强调色和你自己的气泡颜色；`--accent-wash` 也从强调色算出来，所以换色不用逐处改。模型凭据只留在后端。
- bot 可以操作你正在用的这台电脑（桌面版就是这台 Mac，不用先运行命令；第一次会问你允许），也可以操作一台连上来的云端电脑。三个工具按目标分工，提示词也按目标写：`computer_shell` 跑终端命令，网页上的数据也先用它（curl、python3 一次拿到结构化结果）；`computer_browser` 在两台电脑上都按元素编号操作网页：云端沙盒里用 [browser-use](https://github.com/browser-use/browser-use)，本机则开一个 Cubes 自己的 Chrome 窗口（独立配置、看得见、可以接手登录），每次返回 `[编号]<标签 属性/>` 元素清单，还能读正文（`read_text`）、整页查找（`search_page`）、执行一段 JS 拿结果（`run_js`）和看控制台错误（`console`）；`computer` 看截图按像素操作，可以 `zoom` 放大一小块；本地图片用 `view_image` 直接看，不用先打开图片程序再截屏。每次任务第一次使用时先问你「允许」，之后这次任务不再逐一询问；同一时间只有一个任务在用。

### 运行过程与可靠性

- 主管验收（「设置 → 团队」里开关，默认关）：主管用 `ask_agent` 咨询成员或用 `direct_message` 私信成员拿到回答后，先用自己的模型对照它布置的任务和用户的原始请求检查一遍，回一个 `{"verdict":"pass"|"revise","feedback":…}`；不合格就把意见交给成员重做，最多打回 1–3 次（可设），会话里出现「打回「X」：…」「验收通过「X」（打回 N 次后）」这样的行动行，到上限仍不合格就按现有结果交付。验收调用不带工具，算作这次任务的一次模型调用，用量记在主管名下（用途 `review`）；看不懂的回答一律当通过。设置存在 `meta` 里，`GET`/`PATCH /settings/team`，改完推送 `team_settings` 事件，下一次调用就生效。
- 每次运行的过程都能回看：任务写下的每条消息都带 `run_id`（包括被咨询成员在群里的回复、机器人私聊和来源标记），参与过的机器人记在 `run_participants`（第 15 版数据库迁移新增）。回复下面的「查看过程」、运行出错的提示条、右键「查看这次的过程」和成员档案里的「最近参与」都能打开「运行过程」：一张交接图（你 → 第一位回答者，@ 接力、咨询、私信、打回各一种线，打回画成回头的弧线），下面是这次运行的全部消息，可以播放 / 暂停 / 单步 / 拖动回放。接口是 `GET /runs/{id}/trace` 和 `GET /conversations/{id}/runs`；迁移前的旧运行按时间窗口找回消息。
- 团队简报（「设置 → 团队」里开关）：每天或每周固定时间，主管调用只有它能用的 `team_report` 工具拿到这段时间的事实（每位成员的回复、任务、失败、验收、用量，未完成的任务和失败的运行），在主管私聊里发一段「做了什么 / 谁花了多少 / 卡住了什么 / 建议下一步」。它是一个系统定时任务（`scheduled_tasks.system`），不出现在「定时」列表里、不占 20 个的名额，照常按定时任务的方式在后台运行和送达；「现在生成一次」对应 `POST /settings/team/digest/run`。
- 两位机器人之间可以互发私信：它们会出现在工作区里，用户可以打开旁观但不能发言。对方的私聊里只留下「消息来自 X」「已发消息给 X」这样的来源标记，不含私聊内容；只有当这次私聊产出了用户该知道的事（决定、成果、阻塞、风险）时，AI 才会用自己的话向我汇报一两句，而不是转发对方的原文。
- 停止会打断当前会话的整个接力队列，并保留已生成内容。群里的这一轮如果只留下工具步骤、还没写出回答，会补一句「已停下：……」（用最后一步的摘要；什么都没查到就写「还没有结论」），并记住是谁被打断：下一句「继续」「接着」直接回到它，不再经过分发员。停止后重读当前打开的会话，避免别的群里留下「正在生成」。发送失败会保留草稿，并在离开会话后仍提示。停止失败单独提示，不会伪装成会话断流。

### 命令行

- 命令行和 MCP：`cubes`（`backend/scripts/cubes`，或在 `backend/` 里 `python -m cubes_cli`）可以从脚本里看团队、给某个机器人或群组派活、等它做完再取回回复；`cubes mcp` 通过 stdio 给 Claude Desktop、Cursor 这类客户端提供四个安全工具（列机器人、派活、等完成、取结果），不能同意卡片、不能删除，也不返回密钥。桌面版每次启动把当前端口和令牌写进 `cli.json`，命令行不需要任何参数。详见下文「命令行和 MCP」。
