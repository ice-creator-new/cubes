# Cubes · 主管驱动的自主团队

## 已确认方向

用户要求大幅改造固定角色圆桌：默认只有一位自由配置的主管，由主管自行创建角色、群组并组织协作；头像使用 Alain00/blobatar。用户选择「任务驱动的自主团队」：交代目标后主管自主行动，不逐项确认创建；完成后等待新指令，不主动安排持续后台任务。角色和群组长期保留。

本规格替代固定三角色、最少两角色开局和按轮数轮流发言的旧产品机制。保留原生 SwiftUI、Python 后端、现有模型服务和系统/浅色/深色外观。

## 用户体验

### 默认入口

首次启动团队中只有一位主管，不创建固定专家。首页是会话列表，置顶主管私聊；空团队通过主管头像、简短介绍和输入建议引导用户描述目标，而不是先配角色和轮数。

主管的默认名字是「主管」，名称与职责指令可编辑。主管身份通过持久 ID 与角色类型识别，不通过名字判断；改名不改变权限或头像。

### 任务执行

用户把目标发给主管。简单问题允许主管直接回答；需要协作时，主管自主检查现有成员与群组，决定复用还是创建新角色、新群组，并指定谁处理什么。角色数量、名称、专业方向及发言顺序不预设。

主管只能通过后端真实执行工具完成操作。聊天里显示结构化行动记录，例如「创建了产品研究员」「建立了产品验证群」「正在咨询交互设计师」。创建的成员与群组立即出现在团队和会话列表中，点击行动可打开真实实体。自然语言声称创建不算成功。

各成员收到自己的职责、目标群的历史及主管给出的任务，产出的回复写入对应群组并实时显示。主管看到工具结果后决定继续询问、组织观点交锋，或向用户汇总结论。没有固定每人发言一轮的流程，也不要求每个问题都建群。

用户可向已有群组发送新目标，由主管按该群上下文组织后续协作。用户也可查看成员详情、修改名称与职责以及调整群组成员；不添加账户、文件访问、浏览器、终端、外部执行工具。

### 页面结构

- **会话**：主管私聊置顶；群组会话展示头像、最近消息、时间和运行状态；可以进入已有群组继续任务。
- **团队**：主管与动态创建的成员列表，展示 Blobatar 头像、姓名、职责摘要；成员详情显示完整职责与参与群组。
- **聊天**：用户/成员消息、流式文本、思考与工作状态、结构化行动记录、停止按钮、可继续发送的输入框；群组页可查看成员。
- **设置**：保留后端地址、真实模型配置状态、系统/浅色/深色外观。

页面以聊天和工作过程为核心，不保留旧首页角色轨道图、轮数选择器或固定三角色编辑表。继续复用已安装的 SwiftPieces GlassSurface；正文保持高对比度不透明底色。

## 后端领域模型

使用独立的持久实体，而不是把角色提示词塞进每场会话：

- **Agent**：id、name、instructions、kind（supervisor/member）、avatar_seed、created_at、updated_at。
- **Conversation**：id、kind（direct/group）、title、purpose、成员关系、创建与更新时间。主管私聊只有一个，群组成员引用 Agent ID。
- **Message**：id、conversation_id、author_id、author_name_snapshot、kind（user/agent/action）、content、status、时间与有序序号。作者快照保证改名后旧消息仍可正确归属。
- **Run**：id、目标会话、用户目标、status、当前工作说明、模型调用与工具执行计数、错误、创建与结束时间。
- **Action**：run_id、tool_call_id、工具名、参数、执行状态、结果及相关实体 ID；供聊天展示真实操作结果和持久化审计。

一个本地工作区只保留一个主管。全工作区同一时刻只有一个活跃任务，可以跨群组协作；用户可以浏览其他页面，但不能同时启动第二个自主任务。明确返回运行冲突，而不是悄悄串行排队。

角色、群组、消息、行动均存入 SQLite。服务重启后已有实体和文本保留；未完成任务标为中止，不偷偷恢复模型调用。用户重新发指令后才继续。

## 主管的工具边界

采用 OpenAI 兼容 Chat Completions 的原生 tools/tool_calls 协议，不用正文里的伪 JSON 或关键词匹配冒充工具执行。

主管可用工具：

1. **create_agent**：创建具有自定义名称、职责的成员，返回持久 ID 和头像 seed。
2. **create_group**：用名称、目的和现有成员 ID 建群；主管自动成为群成员。
3. **set_group_members**：调整指定群成员，不能移除唯一主管，不能引用不存在的角色。
4. **post_group_message**：主管向群组发布任务说明或阶段结论。
5. **ask_agent**：指定群组中的一位成员处理具体问题。该成员基于该群上下文真实调用模型，结果保存为该群消息并返回给主管。

每次主管模型调用获得当前会话历史、团队/群组目录和本任务工具结果，不把所有私聊与所有群聊记录无差别拼成全局上下文。成员只能读取被委派的群组上下文；不能自行调用创建工具或递归启动主管。

同一轮多个工具调用按模型给出的顺序实际执行，并用正确的 tool_call_id 回传结果。工具参数和成员归属在服务端校验；已成功的建人/建群操作不会因后续模型错误而回滚或重复创建。未知工具、无效参数和上游拒绝必须显示真实失败信息，不伪造结果。

成员之间的多次交流由主管依据已有群消息动态安排，不使用固定轮次或固定三种职责。工具完成不等于任务完成；以主管最终答复或停止/错误/预算终止作为任务终态。

## 自主运行与停止

不新增定时任务或常驻自聊。应用离开聊天页面只停止客户端订阅，Python 仍继续当前任务；再次进入读取最新快照。

单次任务具有可配置上限，默认：最多 16 次模型调用、32 次工具执行、8 个新成员、4 个新群组。上限限制单次任务的消耗，不限制已有团队必须是固定人数。达到上限时明确结束任务并保留已生成的文本和实体，用户可发送新指令继续；不把未完成任务标成成功。

停止覆盖本次主管及其当前成员调用：取消正在进行的上游流，不再启动新调用，持久化部分文本并将未完成消息标为中止。不能通过直接销毁 HTTP 订阅实现停止。

SSE 保留经过验证的字节分帧客户端、明确终态和订阅前快照一致性规则。增加团队/群组/行动/任务事件，让客户端无需从自然语言猜操作或工作状态。流提前结束与无效数据仍显示错误并支持手动重载，不增加隐式重试。

## Blobatar 头像

已核实仓库为 MIT 许可证；官方 HTTP 端点返回真实 SVG：

`https://blobatar.dev/avatar/<encoded-seed>?gen=2&background=squircle&size=192`

- 为主管、成员生成持久随机 ID 作为 avatar_seed，不用姓名、模型凭据或聊天内容作为第三方 URL 参数。
- 固定 gen=2，确保改名、重启和外观切换不会换脸。
- Python 获取真实 Blobatar SVG，以 resvg 的 Python 绑定栅格化为 PNG 后缓存；iOS 用原生图像显示，不为每个头像嵌入 WebView，也不引入 Node 后端。
- 同一 seed 缓存复用；缓存存在时无需再访问官方服务。首次获取失败显示明确加载/失败状态并允许重试，不用表情或随机几何图冒充 Blobatar。
- 群组使用成员头像组合，身份仍来自实际成员。
- 保留原始许可证和来源说明。官方端点有限流和第三方可用性风险，不声称离线初次生成或有服务可用性保证。

## 数据迁移与现有配置

保留现有 backend/.env、上游地址 http://model.mify.ai.srv/v1 及用户已配置的模型，不展示或覆盖密钥。

旧 SQLite 在迁移前先备份，使用版本化事务迁移；失败时保持原数据可恢复。旧讨论转换为历史群组，原话题、消息顺序、作者姓名、角色设定快照和生成状态保留。旧固定角色不自动注入新的活动团队；新团队默认仍只有主管。继续旧话题时，主管读取原讨论记录并按新机制决定团队结构。

迁移完成后切换全部 iOS 调用与后端接口，移除旧固定轮次调度、最少两人约束及废弃路径，不维持两套并行产品机制。旧角色快照仅作为历史数据，不作为兼容执行层。

## 接口与实现边界

Python 负责主管初始化、实体 CRUD、消息写入、模型工具循环、真实成员调用、任务预算、停止、持久化和头像代理缓存。iOS 负责会话/团队/成员/群组界面、真实事件呈现、图像缓存、外观和设置。

在实现计划中冻结 agents、conversations、runs 和事件流的精确 JSON 契约，再并行改造前后端。继续使用单进程服务，不添加公网账户、多人权限、第三方操作或自动调度功能。

## 验收

- 全新数据库启动后只有一位主管，能直接聊天，不要求先创建第二位角色。
- 给出协作目标后，真实模型通过工具创建非预设成员和群组，实际持久化并实时出现在 iOS；不能靠预置名字或固定角色匹配通过。
- 主管咨询成员，成员真实回复进入所属群；后续成员能看到该群先前回复，主管再给出真实最终答复。
- 简单问题不强迫建人建群；下一次任务能够复用已有成员和群组。
- 停止、预算终止、工具错误、模型拒绝和重启均保留已完成实体与部分文本，且无后续偷偷继续调用。
- 单任务冲突、重复工具调用身份、非法成员引用、跨群上下文隔离有确定性行为测试。
- 原有讨论经迁移后仍能查看和基于原记录继续，现有 .env 保留。
- Blobatar 为真实来源、身份稳定、有缓存，模拟器检查浅色/深色头像和各页面可读性。
- 通过真实模型完成一次「主管 → 创建成员 → 建群 → 成员协作 → 汇总」端到端场景，并在模拟器观察实际实体和消息；另外用隔离上游验证失败边界。
