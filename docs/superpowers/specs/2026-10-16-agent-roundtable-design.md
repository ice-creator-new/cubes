# Cubes · Agent 圆桌设计

## 目标

在现有 SwiftUI 工程中实现原生 iOS 多 Agent 圆桌应用，并提供 Python 后端。用户给出话题，不同角色轮流阅读共享讨论记录、回应其他角色，最终由综合角色形成总结。不是并发生成互不相关的回答。

## 已确认的产品方向

用户选择「采用设计：圆桌讨论」。默认三个可编辑角色：提出方案、质疑论证、综合总结。可以设置讨论轮数、中止正在进行的讨论、在一轮讨论完成后补充问题并继续。每位 Agent 的名称与角色提示词可编辑；至少需要两位 Agent。

界面包含话题入口、Agent 配置、实时讨论时间线与历史记录入口。消息区显示角色身份、角色颜色、生成状态和正文。没有 API Key 或网络不可达时呈现真实错误，不生成假回复。

## 原生界面

使用 SwiftUI。按用户对首版视觉的反馈，首页重做为紧凑的成员、话题输入、建议话题和真实历史布局，移除大幅角色轨道图与重复角色卡片。实际通过 SwiftPieces MCP 安装 GlassSurface，用于建议话题、轮数控件、角色标识和思考提示，保留原始许可证；流式正文交互参考 StreamingReply、ThinkingState 和 PromptChips。正文使用高对比度不透明底色，遵守减少动态效果与减少透明度设置。

本项目现有部署版本为 iOS 27；Liquid Glass 使用已验证的 SwiftUI API，不引入网页界面。

支持跟随系统、浅色、深色三种外观，在设置中切换并持久保存。首页、讨论、历史、角色编辑和设置均适配深色；设置面板切换时即时更新自身外观。

## 系统边界

- iOS：角色与轮数编辑、会话列表、流式渲染、停止和继续、后端地址设置。
- Python/FastAPI：模型调用、共享上下文、顺序调度、会话持久化、生成任务生命周期。
- SQLite：会话、角色快照、消息和讨论状态；服务重启后保留已有记录，并将未完成生成标记为已中止。
- 模型上游：`http://model.mify.ai.srv/v1`，按 OpenAI 兼容的 Chat Completions 接口接入。实际兼容性需联调验证。

## 配置与凭据

后端从 `.env` 读取 `MODEL_BASE_URL`、`MODEL_API_KEY` 和 `MODEL_NAME`。示例中 `MODEL_BASE_URL=http://model.mify.ai.srv/v1`，API Key 留空；不猜测模型名称，由使用者填写。缺少必要配置时给出可操作的配置错误。`.env` 不提交，iOS 不持有上游密钥。

iOS 的后端地址可配置，模拟器默认访问本机服务；真机使用可访问的局域网地址。开发环境所需本地网络与 HTTP 配置限定并在启动说明中解释。用户指定的上游使用 HTTP，不声称具备传输加密。

## 讨论流程

1. 用户提交话题、角色和轮数，后端创建会话。
2. 每轮按角色顺序调用模型。角色收到自己的系统指令以及标明发言人身份的共享消息记录。
3. 最后一位综合角色在该轮结束时总结共识、分歧和待解决问题。
4. 后端通过服务器发送事件（SSE）发送状态、消息起始、文本增量、消息结束和错误。客户端离开页面后重新打开时读取会话快照，不额外实现自动重试或断点重连协议。
5. 用户停止时后端取消当前上游请求，保留已有文本并标注未完成状态；不继续启动后续角色。
6. 一次会话同一时刻只能有一个讨论任务。完成或中止后可提交新问题继续；继续时保留旧消息上下文。
7. 网络错误、上游拒绝、无效响应与空结果均以真实错误结束当前任务，保留已完成消息。

## 接口范围

提供健康状态与模型配置状态、会话列表/详情、创建会话、启动或继续讨论、停止讨论、SSE 事件流接口。接口数据结构使用显式角色 ID、消息 ID 和会话状态，客户端不通过正文判断状态。

## 不在范围内

账户系统、公开部署鉴权、多人协作、工具调用、联网搜索、语音、计费和后台无限运行。后端面向本地开发与受信任网络，不作为无鉴权的公网服务部署。

## 验收与验证

- iOS 工程可以构建并在可用模拟器上运行；实际检查主页面、角色编辑、讨论与错误状态。
- 后端运行后通过真实 HTTP 请求验证会话创建、持久化、流式事件、停止、继续和重复启动冲突。
- 使用隔离的本地 OpenAI 兼容上游验证跨角色上下文、流式响应与错误行为；测试上游不进入生产代码。
- 若用户未填写上游密钥和模型名称，不能证明指定模型服务的真实生成成功；明确报告该限制，并验证缺配置提示。
- 提供依赖安装、`.env` 配置、后端启动与模拟器/真机连接说明。
